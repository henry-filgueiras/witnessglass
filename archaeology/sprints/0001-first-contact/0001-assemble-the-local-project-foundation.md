# Assemble the local project foundation

## Objective

Assemble the local WitnessGlass project foundation: a minimal Rust binary scaffold that
compiles and honestly reports that recording is not implemented, the README and agent
contract that state the project's epistemic commitments, dual licensing, a single local
check gate, a CI workflow that runs that same gate, and an initialized Scarp corpus
carrying the inaugural decisions, dragons, sprint, and tasks.

The foundation is deliberately small. Nothing here implements recording, and nothing here
lays speculative groundwork for it.

## Acceptance criteria

- `Cargo.toml` declares edition 2024, `license = "MIT OR Apache-2.0"`, the repository URL,
  and `publish = false`, with no dependencies and no MSRV declared yet.
- The binary compiles, prints a clear bootstrap-only diagnostic, and exits with failure. It
  does not print "Hello, world!" and does not expose a pretend command surface.
- `README.md` carries the positioning line, a prominent bootstrap-only status, the
  witness-glass name origin, the problem, the reported/observed/derived distinction, the
  cooperative-hooks-first direction with its admitted blind spots, the SignalScope lineage,
  the Scarp dogfooding relationship, current non-goals, development instructions, and the
  dual-license statement.
- `CLAUDE.md` states the identity mapping, the core epistemic invariant, canonical versus
  derived state, the capture boundary, the privacy posture, bootstrap non-goals, the Scarp
  workflow, desire-path dogfooding rules, the check gate, and git authority.
- `LICENSE-MIT` and `LICENSE-APACHE` are both present.
- `scripts/check.sh` is executable, uses strict shell error handling, and runs `cargo fmt`,
  `cargo clippy` with warnings denied, `cargo test`, and `scarp doctor`.
- `.github/workflows/ci.yml` runs on push and pull request, uses read-only contents
  permission, a current `actions/checkout` major, installs rustfmt and clippy, installs
  exactly `scarp 0.2.0` with `--locked`, and invokes `scripts/check.sh` so CI and local
  semantics stay shared.
- The Scarp corpus contains both inaugural decisions, both inaugural dragons, this sprint,
  and its four tasks; `scarp doctor` reports the repository healthy.
- `scripts/check.sh` passes locally, the diff contains no credentials, machine-specific
  paths, scratch files, or recordings, and the foundation is committed.

### Scarp desire paths observed

Two, both genuine and both hit while doing this work rather than while probing the tool.

**Recording a task result requires hand-editing the artifact.** Scarp owns task creation
and the close transition, but has no command that writes a result, and the task template
has no `## Result` section. Attempted workflow: create task with `--body-file`, do the
work, record the outcome, close. Friction: the outcome step has no Scarp affordance.
Workaround: append a heredoc to the task file with a shell redirect, then `scarp close`.
Smallest useful affordance: `scarp close task:N --result-file <path>`, appending the result
and moving the status in one write. Promoted to idea:1.

**A collection's section headings are not discoverable before its first artifact exists.**
`--body-file` requires `## ` headings that match the collection's own sections, but no
command prints them, and an unrecognized heading fails quietly rather than loudly. Attempted
workflow: write nine body files up front and create every artifact in two batched commands.
Friction: the required headings were unknowable from the CLI. Workaround: `scarp init` a
throwaway repository in the scratchpad, create one artifact per collection, read the
generated templates, discard it. Smallest useful affordance:
`scarp new <collection> --print-template`, or making an unrecognized body-file heading a
hard error that names the expected sections. Promoted to idea:2.

Neither was worked around by modifying Scarp, and nothing has been sent upstream.
